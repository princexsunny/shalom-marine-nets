# Deploying Shalom Marine Nets for free

This is a **Node.js/Express** app (server-rendered + file uploads + JSON/Firestore store), so it
needs a Node host. Static hosts (GitHub Pages, Netlify, Vercel static, Firebase Hosting alone)
**cannot** run it.

## Recommended: Render (free, no credit card)

1. **Create a GitHub repo** and push this project. `serviceAccountKey.json`, `node_modules`,
   `data/app.json` and `public/uploads` are already git-ignored.
2. Go to <https://render.com> → **New → Blueprint** → connect the repo. Render reads
   `render.yaml` (build `npm install`, start `node server.js`, free plan).
3. **Upload your current data to Firestore FIRST** (see step 5 below). `data/app.json` is
   git-ignored, so the deployed app starts blank and pulls its data from the cloud backup.
4. In the service **Environment** tab add:
   - `FIREBASE_SERVICE_ACCOUNT` = the entire service-account JSON (one line).
   - `FIREBASE_STORAGE_BUCKET` = `your-project.appspot.com`.
   - `SESSION_SECRET` is auto-generated by the blueprint.
   - `FIREBASE_RESTORE` is **not** normally needed — the app now restores automatically
     whenever it boots with no trading data. Set it to `1` only to force a restore
     *over* existing data.
5. **Upload your existing data to Firestore** — run this locally, with
   `serviceAccountKey.json` in the project folder:

   ```bash
   node -e "const {store}=require('./db');store.startCloudMirror();setTimeout(()=>{console.log('uploaded');process.exit(0)},4000)"
   ```

   Check **Firestore → app → state** in the Firebase console; you should see a `json` field.
   Skip this and your live site comes up with the 8 demo products instead of your catalogue.
6. **Create Web Service** → wait for the build → open `https://<name>.onrender.com`.
7. Log into `/admin` (default `admin` / `admin123`) and **change the password** under Account.
   The server logs a warning on every start until you do.

### Checking the deploy worked
In Render's **Logs** tab, a healthy first boot shows:

```
[firebase] Admin initialized — Firestore + Storage + Auth
[firebase] state restored from cloud backup (blank instance)
```

If you see the demo products (Purse Seine, Gill Nets…) instead of your own, the restore
didn't run — check `FIREBASE_SERVICE_ACCOUNT` is set and `app/state` exists in Firestore.

### Free-tier caveats
- **Cold start:** the service sleeps after ~15 min idle; the next visit takes ~30–60s to wake.
  (A free uptime pinger like UptimeRobot can keep it warm.)
- **Ephemeral disk:** the filesystem resets on every deploy/restart. **Enable Firebase**
  (Storage + Firestore, above) so uploads and data survive — otherwise admin changes and
  uploaded images are lost on redeploy. See `FIREBASE_SETUP.md`.

## Other options
- **Railway / Fly.io** — good Node hosts but now require a credit card even for trials.
- **Firebase Hosting + Cloud Run** — works (natural fit since you use Firebase) but Cloud Run
  needs billing enabled (has a free tier, card required). Ask me and I'll add a `Dockerfile`.
- **A VPS** (Oracle Cloud Always-Free, etc.) — truly persistent disk, but more setup.

## Production checklist
- [ ] `SESSION_SECRET` set (stable across restarts).
- [ ] Firebase configured (data + upload persistence).
- [ ] Admin password changed.
- [ ] Contact details, hero media and products set in the admin.
- [ ] Custom domain (optional) added in Render + `canonical`/`og:image` switched to the real URL.
